# soft — مشروع شرفسوفت

هذا المستودع يحتوي على نسخة قابلة للتعديل وإعادة البناء من تطبيق **شرفسوفت** اعتمادًا على ملف APK المرفق. تم الاحتفاظ بالموارد الأصلية، وملف `AndroidManifest.xml`، والأصول، والخطوط، وملفات Smali، وجميع مجموعات DEX الخمس. لذلك فإن التعديلات الحالية لا تعيد تصميم التطبيق ولا تغيّر واجهته أو سلوكه تلقائيًا.

> ملاحظة مهمة: ملف APK لا يحتوي على مشروع Kotlin/Java الأصلي. لهذا السبب تم الاحتفاظ بالكود بصيغة Smali الناتجة عن التفكيك، وهي الصيغة الأقرب إلى ما يمكن إعادة بنائه مع الحفاظ على التطبيق كما هو. أسماء كثير من الأصناف قد تكون مختصرة أو غير واضحة بسبب التحسين/التشويش الذي حدث قبل إنتاج APK.

## بنية المشروع

| المسار | الغرض |
|---|---|
| `app/AndroidManifest.xml` | تعريف الحزمة والصلاحيات والأنشطة والخدمات |
| `app/smali*` | الكود المفكك، موزع على خمس مجموعات DEX |
| `app/res` | الموارد والواجهات والألوان والأيقونات |
| `app/assets` | ملفات HTML وExcel والخطوط والصور والملفات المساعدة |
| `original.apk` | النسخة الأصلية المرجعية التي تُستخدم كأساس للحفاظ على الموارد والتفاصيل |
| `tools/build-apk.sh` | تجميع Smali وحقن ملفات DEX الجديدة داخل APK الأصلي |
| `.github/workflows/build-apk.yml` | بناء APK تلقائيًا عند كل Push أو يدويًا من GitHub Actions |

## التعديل

تُعدّل الواجهات والموارد داخل `app/res`، وتُعدّل الملفات المساعدة داخل `app/assets`. أما منطق التطبيق فيوجد داخل مجلدات `app/smali` و`app/smali_classes2` حتى `app/smali_classes5`. يجب عدم إعادة تسمية الحزمة أو الأنشطة أو حذف الصلاحيات والمكونات من Manifest إلا عند الحاجة، لأن ذلك قد يغيّر سلوك التطبيق.

## البناء المحلي

على Ubuntu يمكن تثبيت المتطلبات ثم تنفيذ:

```bash
sudo apt-get update
sudo apt-get install -y libsmali-java zip
chmod +x tools/build-apk.sh
tools/build-apk.sh dist/soft-unsigned.apk
```

ينتج السكربت APK غير موقّع في `dist/soft-unsigned.apk`. يحذف السكربت توقيع النسخة الأصلية من الناتج لأن أي تغيير في DEX يجعل التوقيع القديم غير صالح. يقوم GitHub Actions بمحاذاة APK وتوقيعه تلقائيًا بمفتاح CI مؤقت، ثم يرفعه كـ Artifact باسم `soft-apk`.

## GitHub Actions

يعمل البناء تلقائيًا عند الدفع إلى فرع `main`، ويمكن تشغيله يدويًا من تبويب **Actions** عبر اختيار **Build APK** ثم **Run workflow**. بعد نجاح المهمة، افتح صفحة التشغيل وابحث عن Artifact باسم `soft-apk` لتنزيل `soft.apk`.

> مفتاح التوقيع المستخدم في الإجراء مؤقت خاص بالبناء. إذا كان المطلوب تحديث تطبيق مثبت فوق نسخة منشورة سابقًا، فيجب استخدام مفتاح التوقيع الأصلي لذلك التطبيق بدل المفتاح المؤقت؛ وإلا سيعتبر Android النسخة تطبيقًا مختلفًا عند التحديث.

## الحالة الحالية

تم اختبار مسار إعادة التجميع محليًا، وتجميع مجموعات DEX الخمس، وحقنها داخل APK الأصلي، والتحقق من سلامة أرشيف APK الناتج. لا يمكن ضمان التطابق الثنائي الكامل مع APK الأصلي لأن إعادة تجميع Smali تغيّر بعض تفاصيل DEX الداخلية، لكن الموارد والـ Manifest والأصول الأصلية تُستخدم كأساس للحفاظ على التفاصيل المرئية والسلوكية.
